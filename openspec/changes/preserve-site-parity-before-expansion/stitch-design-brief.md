# Stitch Design Brief

## Goal

Redesign the full `econoben.dev` site as one coherent system, not just a homepage.

The site should feel practical, editorial, and technically credible. It should support:

- posts
- talks
- publications
- about / CV
- code and tools
- archive
- tags
- search
- book

Do not turn the site into a book microsite. The book should be integrated as one part of a broader personal platform.

## Core Design Direction

- Practical over performative
- Editorial over flashy
- Clear and useful over self-conscious
- Calm, credible, and technically literate
- Consistent across desktop and mobile

Use the uploaded Figma screenshots as the strongest visual reference for the intended direction, especially for spacing, hierarchy, and overall tone.

## Tone and Language Constraints

- Use `Posts`, not `Essays`
- Do not call content `pieces`
- Avoid braggy or pretentious framing
- Avoid vanity summary stats like total talk counts or "latest appearance"
- Preserve existing wording by default unless a clearer label is necessary

## Global System Constraints

- Preserve all existing routes and content surfaces
- Keep explicit `Home` navigation
- The full site family should share one theme system
- Support both desktop and mobile layouts
- Preserve practical browsing and discovery behavior

## Page Family To Design

### 1. Home

Design a home page that introduces Ben clearly and makes it easy to move into posts, talks, publications, and the book. Keep the book/newsletter callout subtle.

### 2. Posts Index

Design a posts archive/discovery page, not a magazine-style essays page. Preserve dates, summaries, tags, and direct links.

### 3. Post Detail

Design for long-form technical reading. Support markdown, code blocks, diagrams, math, metadata, tags, and optional audio playback.

### 4. Talks

Design around watch/listen utility first. Preserve embedded video/audio playback and transcript links where available. Do not use braggy summary stats or venue stripes.

### 5. Publications

Design a useful browse-first publications page. Separate books, reports, papers, and other work clearly. Avoid empty metric cards or filler sidebars.

### 6. About / CV

Keep this as a practical CV/profile page. Resume access and work history should stay prominent. Do not turn it into an author manifesto.

### 7. Code & Tools Index

Design this as a practical tools/snippets/workshop library with categories, search, and compact/full browsing.

### 8. Code & Tools Detail

Design a readable code-detail page with metadata, gist/GitHub link, breadcrumb, and code-first presentation.

### 9. Search

Design a direct, utility-first search page that still feels native to the rest of the site.

### 10. Archive Index

Design a chronological archive page with clear year/month grouping and scan-friendly navigation.

### 11. Archive Month

Design this as a month-filtered variant of the posts list.

### 12. Tags Index

Design a tag discovery page that preserves tag visibility and counts.

### 13. Tag Detail

Design this as a filtered variant of the posts list for one tag.

### 14. Book

Design the book page as part of the main site, not a separate brand. It should feel consistent with the rest of the platform.

## Deliverable Expectation

Create a complete site family with a shared design system and page-specific layouts for all of the pages above.

Start from the uploaded visual references, but extend them into a practical, consistent multi-page website system.
